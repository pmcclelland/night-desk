NIGHTDESK Tape polling · SNAP | LIVE · REST, no sockets

The tape is four timers, not a stream.

NightDesk never opens a websocket or SSE. LIVE is a client-side poll loop. SNAP is that loop torn down, plus a gate on the fetchers so leftover timers cannot keep spending. One snapshot still fires on load.

SNAP · default

One burst, then quiet

Persist liveFeed: false in nightdesk.v1. Boot hydrates the desk, pulls quotes, draws bars, and (if the venue is Alpaca) snapshots the book. Then stopLiveLoop() runs. Recurring spend stops.

LIVE · opt-in

Polls while this tab is open

Setting LIVE immediately refreshes quotes and the Alpaca book, then starts four setIntervals plus a visibility listener. Background tabs pause. There is no server cron.

Run the loop

T+0.0s

Boot, then maybe the loop

TerminalShell mounts two independent effects. The empty-deps effect is the SNAP snapshot. The liveFeed effect is the loop.

  1. hydrateDesk({ force: true }) — pull Neon desk. Shared in-flight promise so Strict Mode cannot double-pull.
  2. Then refreshQuotes({ force: true }) and refreshBars().
  3. If venue is not SIM, refreshAlpaca({ force: true }).
  4. If liveFeed is false, stopLiveLoop() and return. No intervals.
  5. If true, kick quotes + book once more, then startLiveLoop.

Chart bars are not on the live cadence. Changing symbol or range calls refreshBars() in both SNAP and LIVE. That is a user action.

Three gates

SNAP used to be only gate 1, and only the skip-start half of it. Leftover timers walked through the fetchers unchallenged.

1 · Effect

if (!liveFeed) { stopLiveLoop(); return; } SNAP must tear the loop down, not merely decline to start a new one. startLiveLoop also stops any previous loop first — one set of timers, stored on globalThis so HMR cannot stack copies.

2 · Tick

Each interval and the visibility listener call isLive() (reads useDesk.getState().liveFeed) and skip when the tab is document.hidden.

3 · Fetcher

tapePollAllowed(liveFeed, force) is force || liveFeed === true. Polls pass no force. Boot and user actions pass { force: true }. A leaked timer that still calls refreshQuotes() dies here on SNAP.

One client POST, many vendor GETs

The browser talks only to NightDesk server functions. Spend you see in Alpaca or Yahoo dashboards is the handler fanning out.

SIM uses Yahoo (delayed) then seed. Alpaca paper/live uses IEX; missing names fill from Yahoo. Quote single-flight prevents overlapping POSTs. Strategy ticks are also single-flight, but each armed name is its own bars request inside that flight.

The SNAP leak

Fixed

Skipping start is not stop

The first SNAP implementation gated the effect with if (!liveFeed) return. That does not run cleanup. A loop started by LIVE, by a stacked mount, or by HMR kept its intervals. Those callbacks called refreshQuotes with no SNAP check.

SNAP now calls stopLiveLoop(), the loop is a singleton, ticks read isLive(), and fetchers refuse unforced SNAP polls. Boot and user actions still pass force: true.
