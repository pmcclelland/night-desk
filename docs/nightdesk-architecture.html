NIGHTDESK
Architecture briefing · one desk · one store · three venues

The terminal is the architecture.

NightDesk is a single-route trading terminal. There is no page tree, no user accounts, no shared database. The chrome you see — header, tape, six panels — is a spatial encoding of one Zustand desk store, driven by one action bus, against one of three venues.

Shape of the system

TanStack Start mounts / to TerminalShell. Auth and Postgres stay off. Persistence is the browser’s localStorage key nightdesk.v1. Deployed as a Vercel app; market, trade, and Grok calls are TanStack server functions.

Chrome

IBM Plex · tokens in styles.css · Panel primitive · header, tape, kill, fullscreen.

Layout

Desktop: resizable 2×3 grid. Mobile: five tabs. Chart-focus (F) and immersive (Shift+F) hide chrome, not the tape.

Desk store

useDesk — venue, quotes, bars, selected, sim book, Alpaca snapshot, strategies, bot log, halt, risk.

Action bus

sync.ts — refresh quotes/bars/Alpaca, place/cancel/flatten, kill, strategy ticks, console.

Venues

SIM (in-browser matching) · Alpaca paper · Alpaca live. Views never talk to a venue directly; they read useLiveBook().

Feeds

Server functions: Alpaca IEX first, Yahoo delayed fallback, seeded jitter if both fail. Tape source badge: IEX / YH / MIX / SEED.

The desk as a data map

Click a region. The inspect pane shows which store slices it reads and which actions it fires. Selection is the only coordination key: watch, chart, ticket, thesis, and bot all orbit selected.

Inspect

Click a panel

Each region is a projection of desk state, not its own mini-app.

Why the design looks like this

The visual system is not decoration around the architecture — it is how the architecture is read at a glance. Instrument black and amber LED come from a vehicle-dashboard mood: one intense status color, phosphor green/red only for signed P&L. IBM Plex Mono is the type of a blotter, not a marketing site. Hairline borders and 28px panel headers (Panel) make six independent surfaces share one grammar so a resize does not become six products.

Density

Everything on one plane

A trading desk fails if you context-switch. Watch, chart, ticket, blotter, algos, and bot are simultaneous because they share one selected and one quote map. Mobile cannot fit the plane, so the same components become tabs — not a different app.

Status color

Signed numbers carry the accent

Amber is identity (wordmark, panel titles, armed range). Green/red are only change, P&L, buy/sell, halt. The Kill control is the one red chrome that is not a quote — it is a global write to halted.

Motion

Tape is the live feed made visible

The scrolling tape is the quotes interval (8s) expressed as a marquee. It fills the viewport, then loops on half-width so the last name meets the first. Hover pauses it. Reduced-motion stops it. Chart-focus keeps it.

Safety in chrome

LIVE never persists as LIVE

Venue badge, tape source, and Kill sit in the header because they are process-wide. Persist rewrites alpaca-live to paper so a refresh cannot silently reopen a live desk.

Control plane

Panels do not call Alpaca or Yahoo. They call sync.ts, which branches on venue and writes the store. That is why Halt, Kill, and risk caps apply equally to ticket clicks, bot commands, and armed strategies.

Kill disarms every strategy, cancels working orders, and optionally flattens — same path as a typed HALT.

Market plane

Timers in the shell

  • quotes · 8s
  • Alpaca snapshot · 15s
  • strategy tick · 20s
  • bars · on selected / range
→

server/market.ts

  • Alpaca IEX snapshots
  • Yahoo spark / chart
  • seeded jitter last
→

Fan-out in the UI

  • tape + watch (quotes)
  • chart (bars)
  • header EQ/DAY (book)
  • SIM marks to last

Quote refresh also runs matchWorkingOrders in SIM so limit/stop tickets fill against the tape, then snapshotEquity so the header’s day P&L is the same number the blotter is marking.

Intelligence

Deterministic

Strategies stay on the client

Four kinds — SMA cross, mean-reversion, breakout, momentum — evaluate on 6M bars. Armed names tick every 20s, fire at most once per 15 minutes, and still go through placeOrder / flatten, so Halt and risk caps apply. The Algos panel is a control surface on strategies[], not a second engine.

Language

Bot is a parser with a Grok overflow

parseCommand handles BUY/SELL/FLATTEN/HALT/THESIS/ARM as structured ops. Anything that does not match is askDesk — a server function that spends the app owner’s xAI quota and returns JSON commands, which the same bus executes. The console is the journal: every fill, signal, and error is a botLog line.

What is deliberately not in the architecture

  • No accounts, no user_id, no Neon. A desk is a browser.
  • No WebSocket tape. Polling plus a marquee is the live feel; IEX/Yahoo are request/response.
  • No second store. UI flags (mobile tab, immersive, chart-focus, settings) live next to the book.
  • No live-venue persistence. Reloading a live session falls back to paper keys still in storage.
