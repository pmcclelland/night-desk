NIGHTDESK
Architecture briefing · one owner · Neon desk · MCP bot

The terminal is still the architecture.

NightDesk is a single-operator trading terminal at /. The chrome — header, tape, six panels — is a spatial encoding of one desk. What changed: the desk is no longer a browser. Google claims the slot, Neon holds the book, and a personal Grok Bot trades through MCP on the same engine the ticket uses.

Shape of the system

TanStack Start. Deployed on Vercel at nightdesk.pmcclel.land. Native Google OAuth (Better Auth), not the Grok broker. First signer owns desk_owner. Local preview without DATABASE_URL still uses in-memory PGLite; production is Neon. Browser Zustand is a cache that hydrates every 12s and persists through desk-engine.

Gate

/login · Continue with Google · desk_owner slot=1. Non-owners see a claimed-desk wall.

Chrome

IBM Plex · tokens in styles.css · Panel · header (Kill, settings, operator chip), tape, fullscreen.

Layout

Desktop: resizable 2×3. Mobile: five tabs. Chart-focus (F) and immersive (Shift+F) hide chrome, not the tape.

Desk engine

desk-engine.ts — halt, risk, venue, orders, tape lines. Browser and MCP are two clients of one write path.

Neon

Auth tables · desk_owner · desk_state (encrypted Alpaca keys) · mcp_tokens · desk_kv.

Browser cache

useDesk + nightdesk.v1. Selection and tape persist; hydrate must not snap a newer local pick.

Venues

SIM · Alpaca paper · Alpaca live. Views never talk to a venue; they read useLiveBook().

Grok Bot

Custom bot on /api/mcp with a minted ndk_ bearer. Tools trade and speak on the BOT tape. No in-app xAI loop.

Why the design looks like this

The visual system is how the architecture is read at a glance. Instrument black and amber LED: one identity color, phosphor green/red only for signed P&L. IBM Plex Mono is blotter type. Hairline borders and 28px Panel headers keep six surfaces in one grammar so a resize does not become six products.

Density

Everything on one plane

Watch, chart, ticket, blotter, algos, and bot stay simultaneous because they share one selected and one quote map. Mobile tabs the same components — not a different app.

Status color

Signed numbers carry the accent

Amber is identity. Green/red are change, P&L, buy/sell, halt. Kill is the one red chrome that is not a quote — a global write to halted on the engine.

Motion

Tape is the live feed made visible

Quotes interval (8s) as a marquee. Fills the viewport, loops on half-width so the last name meets the first. Hover pauses. Reduced-motion stops it. Chart-focus keeps it.

Safety in chrome

LIVE never persists as LIVE

Venue badge, tape source, and Kill sit in the header because they are process-wide. Client persist still rewrites alpaca-live to paper. Alpaca secrets are AES-GCM on Neon, not in the tab.

Identity and the slot

Google

Native OAuth on the custom domain

Better Auth at /api/auth/* with a NightDesk Google client. Callback /api/auth/callback/google. The Grok broker is preview-only (*.grok-sandbox.com); nightdesk.pmcclel.land cannot use it.

Owner

First signer claims the desk

desk_owner (slot=1). Later Google accounts are signed in but blocked from the terminal. MCP tokens hash to the owner. There is no multi-user blotter.

Control plane

Panels do not call Alpaca. They call sync.ts, which goes through runDeskOp / desk-engine. The Grok Bot hits the same engine via MCP. Halt, Kill, and risk caps apply to ticket, typed commands, armed strategies, and bot tools.

Kill disarms every strategy, cancels working, optionally flattens — same engine path as typed HALT or MCP halt.

Two writers, one tape

Browser

Command tape, not a chat

parseCommand is BUY/SELL/FLATTEN/HALT/THESIS/ARM/CLEAR. Unknown text is rejected: freeform lives on the Grok Bot. THESIS is local indicators only. Clr / CLEAR / MCP bot_clear wipe the tape with a clearedAt so hydrate cannot resurrect it.

Grok Bot

MCP tools on the owner token

desk_status, quotes, place_order, flatten, halt/resume, watch, select, arm, thesis, bot_log, bot_say, bot_clear. Settings mints an ndk_ token once. MCP is pull: the bot only runs when Grok starts a turn. Duplex wake-up (automation webhook) is not built yet.

Hydrate and selection

Shell timers: quotes 8s · Alpaca 15s · strategies 20s · desk hydrate 12s. A click on watch, tape, blotter, or algos is selectSymbol — it persists. Hydrate keeps a newer local pick if the server selected has not changed (MCP select still wins). Persist in-flight must not apply a stale selected over a click that happened during the request.

Intelligence

Deterministic

Strategies stay on the client tick

Four kinds — SMA cross, mean-reversion, breakout, momentum — on 6M bars. Armed names tick every 20s, fire at most once per 15 minutes, still through placeOrder / flatten. The Algos panel is a control surface on strategies[], not a second engine.

Language

Two mouths, one grammar of ops

The BOT panel is a parser and a journal. The Grok Bot is the freeform operator, on MCP, with its own grok.com thread. There is no nested xAI call from the desk. Answers the operator should see on glass go through bot_say.

What is deliberately not in the architecture

  • No in-app Grok agent and no ask_desk. The personal Grok Bot is the language model.
  • No duplex wake-up. MCP does not ring Grok when you type on the tape; a webhook automation would.
  • No WebSocket tape. Polling plus a marquee is the live feel; IEX/Yahoo are request/response.
  • No multi-user blotter. One owner slot. desk_kv is for future features, not a second product.
  • No live-venue persistence in the browser cache. Reloading a live session falls back to paper in localStorage; Neon still has the encrypted keys.
